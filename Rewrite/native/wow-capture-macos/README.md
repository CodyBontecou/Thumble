# Standalone macOS optical capture helper

This Swift package extracts the retained WoW optical capture path without the Thumble desktop product, configuration authority, renderer or input runtime. It builds a library and `thumble-wow-capture-macos`; it is not installed, signed for distribution, wired to the TypeScript service or accepted against real game windows.

Build and synthetic gates:

```sh
swift test -Xswiftc -warnings-as-errors
swift test --sanitize=address -Xswiftc -warnings-as-errors
swift format lint --recursive --strict Sources Tests Package.swift
```

Default/`--status` calls only `CGPreflightScreenCaptureAccess`; it does not request permission, enumerate windows, initialize `NSApplication` or capture. `--request-permission` is the only path calling `CGRequestScreenCaptureAccess`. Both commands emit one u32 big-endian length-framed JSON object: version1, command `wow-capture-permission-status` or `wow-capture-permission-result`, and status `authorized`/`permission-required`. Their distinct types are not capture receipts or evidence of live game capture. No automated gate invokes either OS permission API.

`--capture` reads sequential u32-BE framed requests, refusing zero/over256-byte lengths before payload allocation. Requests match `@thumble/contracts/wow-capture`: version1, command `wow-capture`, opaque uint32 source and canonical positive uint64 generation/receipt strings. Strict flat ASCII parsing rejects duplicate escaped aliases, extra/nested/coercible fields and malformed counters. Replies echo the exact identities with command `wow-capture-result`, fixed `kind:status` or `kind:frame` plus512-byte `frameBase64` and at most2MiB `atlasPNGBase64`. Outputs are bounded before base64 and framing. Invalid framing/request/arguments produce only a fixed framed protocol error and exit1. Every stdout byte belongs to framing; no private identifiers or raw diagnostic payloads are printed.

A child binds one source/generation, with strictly increasing receipts. Its first eligible capture privately pins window ID, PID and exact process-start seconds/microseconds, OS executable path, regular-file device/inode/size/mtime/ctime, window/content rectangle, scale and expected pixel dimensions. No PID-only fallback exists. Native discovery accepts exactly one on-screen layer0 window of `com.blizzard.worldofwarcraft`, at least320 points per side, with an executable under `/_classic_era_/` or `/_forever_/`. The path comes from `proc_pidpath` and must match the running application. Unreadable identity fails closed. Bundle/path selection follows the retained eligibility policy; it is not cryptographic authentication of an actively forged application.

After the screenshot await, the helper re-enumerates exactly one eligible window and compares the full private identity again. PID reuse, executable/file replacement, another eligible window, resize/movement/scale changes, unexpected captured dimensions, source/generation changes or task cancellation reject the result. Changed context latches unavailable until the child restarts. Permission/absent-game/multiple-window/missing-panel statuses remain distinct; none advances game liveness. The parent must allocate a new generation on restart/resize/device reset and remains the sole supervisor for deadlines, cancellation, termination confirmation and replacement. The helper has no competing timeout/restart policy or observer ACK.

Only the same capture's validated512-byte THWL page and normalized256-square PNG leave the process. Whole-window pixels remain transient native memory. The retained8192-per-axis/16,777,216-pixel input bound limits normalized RGBA to64MiB; CoreGraphics may retain additional bounded image/context copies. Discovery remains top-left512-square with a4,194,304sample-read budget; frame checksum/padding validation and2MiB PNG cap remain intact. No capture is written to disk. AppKit is used only for process metadata/display-connection initialization with prohibited activation; no desktop UI product is launched. Native dependencies are Foundation, Darwin, AppKit, ScreenCaptureKit, CoreGraphics, ImageIO and UniformTypeIdentifiers; there are no package dependencies.
