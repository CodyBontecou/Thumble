# Profile resource envelope fixtures

`v1/fixture.json` is generated by the native `ProfileResourceCodecTests.testSharedFixtureMatchesNativeEncodingAndExactExpansion` case. It contains one complete pooled candidate profile, its expanded equivalent and a portable copy with launch metadata removed and unused resources pruned.

The synthetic `fixture-image` bytes exercise byte preservation, aliases, inline image fills, artwork, control states and canonical/variant ownership; they are not a valid image. Real-image native renderer comparisons remain in `Tests/FeatureRemovalBaselineTests.swift` and `docs/feature-removal-evidence/appearance-bank-profile`.

The profile envelope uses `appearanceResourceVersion: 1` and `appearanceResources`, a map from lowercase SHA-256 to canonical Base64. Binary fields contain exactly `{"resourceSHA256":"<digest>"}`. A canonical layout, its mirror controls and all eight owned appearance states share one table. Local launch metadata participates in the same pool, so portable exporters must prune unused entries after removing local-only fields.

The eight-state bank itself still uses its existing schema version. Standalone snapshots/banks retain their ordinary expanded Data codecs; the resource envelope supplies the profile-level context. Native decoding restores shared immutable/COW binary buffers without expanding every reference into repeated Base64 strings. Resource tables are bounded by the existing 8 MiB configuration budget; document/transport limits still apply independently.

These are migration preparation fixtures. Version-5 interchange, authority acceptance, peer negotiation and the atomic upgrade transaction remain disabled or unfinished. Do not treat this fixture as proof of a completed user-data migration.
