# Explicit owned-configuration destination

`v1/document.json` is a hand-assembled version-5 destination specimen, not the output of an activated migration. It combines the native pooled-resource fixture and an existing arcade template's landscape layout, removes the seven retired profile fields, and adds explicit format-5 profile markers. Original fixture sources/hashes are pinned in `v1/manifest.json` and remain unchanged. The specimen includes both a bank-backed and a plain profile, local launch metadata, direct keyboard/controller bindings, resources, unknown nested metadata and an unsigned 64-bit value that must not be rounded through a floating-point projection.

The shared mutation matrix specifies 41 header, profile, layout, resource, reserved-alias, ownership and recovery boundary cases. Explicit Rust, native and Android readers consume the same matrix. Native/Android projections remain separate from the original interchange bytes; edit/write and live authority integration are still required. Existing shipping phone format offers stay at `[4]`.

The version-5 envelope uses the existing configuration schema identifier and `version: 5`. It contains 1...256 profiles, an active declared UUID and an explicit nullable default UUID. Each profile has `profileFormatVersion: 5`, a nonnegative integral update time and exactly one canonical landscape `customization`. There are no skin references/baselines, orientation preferences or separate landscape/portrait variants, including null placeholders or case/punctuation aliases. Standard device frame IDs remain supported. Custom frames use canonical integer portrait dimensions from 240 through 1800 points, smaller dimension first, followed by `-landscape`; this agrees with the native custom-frame editor's whole-point normalization.

Plain profiles own their ordinary appearance directly. A profile with scheme/action differences carries the existing eight-state bank and optional version-1 binary table. Current bank/resource validation also checks the canonical appearance; missing resources and invalid banks require recovery. Canonical layout identity, geometry, groups, executable output and haptics remain independent of state paint.

Authority-global binding mirrors and profile-owned binding maps may be present and are validated against declared controls; exact source values remain in the retained document. A later portable-export operation must deliberately remove local launch data and reconcile its binding/export representation rather than silently dropping fields in this reader. Root credential storage and retired hosted artifact envelopes are rejected. Unknown nonreserved metadata and original numeric spellings/formatting survive through exact original-byte output.

`OwnedConfigurationDocument::decode` is an explicit read-only Rust codec. It does not install state, normalize user data, emit version-4 exports, migrate files or change advertised peer formats. The normal persistent-state configuration validator and install path continue to reject format 5. Edit/write integration, actual transfer admission and backed-up transactional migration still precede activation.
