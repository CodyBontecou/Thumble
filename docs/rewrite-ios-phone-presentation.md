# Native iOS phone presentation

The connected phone installs its strict saved v8 input map before starting optional role10 management reads. The map notification includes `configurationSha256` outside the strict map. A separate `onPresentation` event carries only normalized metadata, individual verified icons, or a fixed error. No credential, endpoint, invitation, source document, resource path, packet grant or input sample crosses that event.

`PhonePresentationRequest` pins the installed storage revision/source hash, profile, native generation/revision, byte-identical logical viewport and materialized configuration hash. Metadata must echo those pins, use base bank and the requested light/dark scheme, contain exactly the installed unique control ID set, and satisfy the shared bounded scalar protocol. The separate presentation revision/hash can advance without changing the active input snapshot. The child alone supplies `observed`, `stale` or `not-evaluated`; a callback is not evidence of game freshness.

`PhonePresentationClient` authenticates a dedicated management role10 connection and permits one metadata read followed by at most64 distinct icon reads. Requests are at most2KiB, metadata frames32KiB and icon frames16KiB. The existing pinned TLS/ALPN/version checks and transport deadlines remain in force. The management wall-clock lifetime uses the existing checked local60-second cap bounded by host and credential expiry, including rollback rejection. Closing or rejecting this client cannot close an input owner: the API has no input-session operations.

Each icon is canonical base64, at most8192 bytes, SHA-256 matched to the pinned control metadata and decoded natively through a bounded zlib validation. PNG must be a32-square, eight-bit RGB/RGBA still image with valid chunk CRCs/order, contiguous image data, exact decompressed scan length and valid scan filters. APNG, unknown critical chunks, trailing data and compressed ancillary `iCCP`, `zTXt` and `iTXt` are rejected. Ordinary bounded `sRGB` and `eXIf` chunks remain compatible with the retained native helper fixture. No image process or capture API is invoked by this verifier.

`PhonePresentationPoller` performs one foreground batch at a time, closes its management connection after metadata and missing icons, then waits two seconds. A successful unchanged metadata response is still emitted. Icons never extend the UI's freshness timer. A verified-icon cache is bounded to64 entries and512KiB raw PNG bytes, keyed by hash; each reused icon is rebound only to matching current metadata. A failed refresh emits a fixed cosmetic error and never replays cached metadata as a fresh observation.

The app supplies a connection-lifetime predicate that checks the exact phone control owner, installed engine, viewport, active window and foreground state. The poller rechecks it after every await and before every notification. Theme changes cancel only the cosmetic connection or sleep and immediately restart the batch; late prior-theme results are discarded. Detach/background/Done cancels polling, closes its socket and clears queued/cache state. The Android app uses a separate executor/socket with main-thread callback and theme-epoch fences, with the same normalized event contract.

Focused tests cover wire/golden agreement, strict source/map/ID pins, authentication role rejection, malformed UTF-8/duplicate keys, frame limits, expiry/rollback, PNG/hash/decompression bounds, cancellation, unchanged metadata refresh, icon reuse, late-owner callbacks and in-flight/sleeping theme changes. A512KiB constrained native thread decodes64 controls and validates64 icons. SDK tests and app compilation are separate from actual phone presentation acceptance; they do not establish gameplay or simultaneous physical multitouch support.
