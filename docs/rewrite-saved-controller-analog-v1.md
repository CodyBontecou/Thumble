# Saved gamepad analog controls

The portable saved-controller projection supports an explicit subset of retained joystick and trigger semantics. It uses the same selected-profile/source/revision pins and control-v8 delivery envelope as buttons. Projection is read-only, preserves the complete owned source and resources, and never activates a receiver. Physical output, skin rendering and gameplay acceptance remain separate.

The six additive action names distinguish these semantics from the existing linear `leftStick`/`rightStick` and binary `leftTrigger`/`rightTrigger` actions. Existing actions keep their behavior. This extends the unreleased v8 action allowlist without adding scalar fields, changing report encoding, widening frame limits or relaxing older protocols. Older strict clients reject an unknown action before admitting input; they must not substitute an old action or standard controller.

| Action                                            | Retained settings                                                                                                                   |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `leftStandardStick`, `rightStandardStick`         | `left_stick`/`right_stick`, pad capture, radial dead zone 0.12, sensitivity 1, no inversion or cardinal snap, no digital directions |
| `leftVerticalTrigger`, `rightVerticalTrigger`     | matching target, vertical, dead zone 0.03, sensitivity 1, no digital button, default digital threshold 0.5                          |
| `leftHorizontalTrigger`, `rightHorizontalTrigger` | matching target, horizontal, otherwise identical trigger settings                                                                   |

Movement and camera here mean gamepad left and right axes. The retained `mouse_look` pointer path is unsupported. Thumbstick activation circles, digital direction/button outputs, primary/default keyboard or button outputs, part mappings and chords are rejected. Selected binding maps may contain only absent or empty output records for analog controls, and no keyboard record. The projector rejects duplicate analog targets even when trigger orientations differ. Unsupported settings produce `saved_controller_unsupported_analog_settings`; binding conflicts and duplicate targets have separate fixed codes.

Every admitted analog control saves explicit zero hit insets, zero rotation/z-index, explicit center and supported scales, with both visual dimensions at least two logical points. The stick saves circle visual shape and absent/`pad` joystick style, while the trigger saves rectangle shape. Retained pad and trigger capture views use the full rectangular bounds; explicit zero insets make those capture bounds equal to the visual layout bounds. The stick normalizes against the rectangle's exact half-width/half-height, rather than a padded hit area. Rendering the native skin or a circular face is not part of this projection.

Logical landscape base sizes follow retained `GamepadCustomization`: stick side `min(128*s, max(82*s, viewportHeight*0.30*s))`; trigger width `min(148*s, max(86*s, viewportHeight*0.30*s))`, height `min(58*s, max(34*s, viewportHeight*0.11*s))`. Saved width/height scales apply independently, and retained center clamping stays unchanged. At 874 by 393 points with standard scale this gives 117.9-point sticks and 117.9 by 43.23-point triggers. Oversized, overlapping, tiny or otherwise unrepresentable regions fail closed.

Native engine integration must preserve these exact transforms. A pad computes `(dx,dy)` from the local point relative to the half-width/half-height, returns zero at radius at most 0.001, then radially clamps the vector to radius one. The 0.12 dead zone returns zero for radius at most 0.12; otherwise the unit vector is multiplied by `min(1, (radius-0.12)/0.88)`. The y-axis remains positive down. For triggers, raw vertical value is `clamp(1-localY/height,0,1)` and horizontal is `clamp(localX/width,0,1)`; value is zero at raw at most 0.03 and otherwise `clamp((raw-0.03)/0.97,0,1)`.

Accepted capture remains owned until end/cancellation, including moves outside the original rectangle; leaving bounds does not turn a continuous trigger into a binary button. End/cancel and lifecycle release zero its target. Native target ownership must include aliases across existing and new action names so a second finger cannot compete for one axis. Sampling and delivery stay native, without per-sample React events.

`saved-controller-analog-v1.json` is a complete synthetic two-profile owned source whose selected profile declares movement, right-stick camera, independent left vertical/right horizontal triggers and South. `saved-controller-analog-control-v8.json` is generated using the actual sole-owner projection and pins both storage and materialized source hashes. Portable tests verify that full path, retained dimensions, all six names, strict negative settings/geometry, target conflicts and exact opaque numeric/source retention. Native engine and real connected SDK/service replay must pass before claiming that this extended subset is usable on a phone.
