# Read-only phone presentation

Phone input and saved presentation have separate lifetimes. The installed control map remains pinned to its original configuration revision, storage source hash, materialized document SHA-256, profile, native generation/revision and exact logical viewport. A WoW refresh can advance saved presentation without changing that input grant.

The sole configuration child records up to eight successful v8 map projections (at most 512 control records), keyed by the full original request and materialized hash. A phone-supplied hash cannot create this baseline. Restart or eviction loses the proof. Before returning newer metadata, the child projects the current selected profile for the same viewport and compares the complete control map: IDs, order, actions, normalized hit rectangles and haptics must match. Missing proof, a different selected profile or changed input semantics returns `presentation_reactivation_required`; the read never releases, activates or rearms input.

Role 10 is a separate authenticated management connection. Metadata returns explicit base/light or base/dark presentation, the current presentation revision/source hash, profile name and up to 64 control labels. Labels and asset names are limited to 128 UTF-8 bytes and are rejected rather than truncated. Canonical element labels and explicit label overrides are read from saved source. This does not infer an action name from an icon, guess a ConsolePort modifier bank, or claim full skin renderer equivalence.

The initial icon subset is an original-rendering asset reference from the chosen base/theme appearance bank. Each referenced PNG must be exactly 32×32, noninterlaced 8-bit RGB/RGBA, no more than8192 bytes and at most 64 PNG chunks. Animated PNG and compressed ancillary metadata (`iCCP`, `zTXt`, `iTXt`) are rejected rather than handed to a platform renderer. The configuration child checks CRCs, compressed input consumption, bounded decompression, scan filters and pixel count before advertising the content SHA-256. Other icon rendering modes or direct layout icons without an appearance bank return `presentation_unsupported_profile`. Saved contents remain unchanged.

Metadata contains no image bytes, source document, file path, atlas or credentials and fits the existing 32 KiB management event budget. Individual icon reads echo the exact metadata presentation revision/hash, original input pins, theme, control ID and content hash. The bytes must belong to that returned control reference and the authority must still match. A source/theme change returns `presentation_stale` and the phone can reread metadata. Icon replies fit 16 KiB and never expose a generic asset-by-hash endpoint. The eight baselines may each retain one current presentation and its verified small icons, bounded by 64 × 8192 bytes per entry; a theme change supersedes the entry's previous icon-read context.

Freshness is `not-evaluated` without a known applied observation. `observed` additionally requires that this exact presentation revision/hash was committed and acknowledged, the current verified capture source/generation matches, and the observer still sees advancing transport for the same applied message. A changed message or source, missing panel, stopped session, expiry or clock rollback is stale. This is correlation with accepted optical observations, not authentication of game state. Frozen pixels or a historical cached acknowledgement cannot renew freshness. A manual snapshot remains usable saved artwork after capture stops, with stale live evidence.

The parent abandons a phone reply after two seconds but retains one underlying child read until it settles; subsequent presentation reads report busy rather than queueing work. The child request uses its existing bounded 30-second owner budget, leaving input packet sampling and owner heartbeats in their independent processes. The native role 10 bridge rechecks the active saved pin and cached authorization around each response and never holds the input/trust lock over configuration reads or TLS delivery. One connection supports up to 65 sequential requests: metadata plus at most 64 individual icons.

This host seam does not itself install phone artwork or certify real-game capture. Tests cover old-map/new-source metadata, changed input semantics, authoritative empty maps, cache eviction/restart, real child IPC, scoped icon reads, malformed PNG/decompression limits and applied-observation freshness. The explicitly authorized retained-helper regression also exercises A/B/A character contexts and changed icon assignments through durable storage and this presentation read path. Native SDK installation, phone rendering and actual-game acceptance are separate evidence.
