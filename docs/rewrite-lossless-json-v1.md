# Lossless configuration JSON v1

The configuration foundation preserves owned-format source without round-tripping unknown metadata through JavaScript numbers. It is separate from the bounded runtime-command JSON codec, retained portable-artifact RFC 8785 hashing, profile validation, credential storage and input admission. No existing document version or migration is activated by this module.

`@thumble/contracts/json` exposes immutable `LosslessJson` values. Parsing accepts a string, retains the exact original text, and creates a private frozen scalar/array/object graph. Objects use ordered entries rather than JavaScript property bags, so names such as `__proto__` remain data. Getters, executable caller objects and cyclic graphs cannot enter through the string-only boundary. Hosts reading files or wire bytes must decode UTF-8 with a fatal decoder before calling this API; a JavaScript string cannot reveal earlier replacement of malformed UTF-8.

The input cap matches the retained owned document's 8 MiB budget. There are at most 131,072 value nodes and 64 levels below the root; Unicode must contain paired scalar values, including after escape decoding. Only JSON whitespace is accepted. Duplicate decoded keys, invalid escapes/grammar, BOMs and unpaired surrogates fail. Business limits on profiles, controls, assets and image decoding remain the responsibility of the forthcoming owned-document model; successful generic parsing is never permission to import or activate a profile.

Numbers retain their exact grammar token, including full-width integers, exponent spelling, decimal zeroes and negative zero. `numberToken` returns that token. `integerValue` is an optional exact safe-integer projection: it reasons from decimal digits/exponent before producing a JavaScript number and refuses fractional or out-of-range results. It never treats a rounded fractional value as an integer. Unknown values need not be representable as a JavaScript number to survive a scoped edit.

`get`, `set` and `remove` use JSON pointers with `~0`/`~1` escaping. Object leaf fields can be added/replaced; array slots can be replaced or removed, and `-` appends. Missing intermediate paths, noncanonical/out-of-range array indices and root removal fail. Every edit returns a new document and revalidates its composed byte/depth/node bounds. Unchanged value subtrees are spliced from original spans, preserving raw numeric/string spellings and internal whitespace; changed containers normalize their own punctuation/key escaping. Parent and sibling documents stay unchanged. These primitives are internal building blocks: remote writes must use typed, capability-scoped application operations with stable profile/control IDs and expected revisions, rather than exposing arbitrary paths.

Canonicalization is explicitly named `thumble-lossless-json-v1`. It sorts decoded object keys by UTF-16 code-unit order, retains array order, emits strings with ECMAScript JSON string serialization and preserves number tokens verbatim. It removes structural whitespace. Equal JSON numbers with different source tokens intentionally have different identities. Host content hashes must be SHA-256 over UTF-8 bytes of `thumble-lossless-json-v1`, a NUL byte and `canonicalText()`. This is a separate source identity from retained portable RFC 8785 integrity; it neither verifies nor replaces an imported artifact's hash. Unknown canonicalization/version identifiers must be refused by future document/receipt codecs.

Serialization accumulates chunks and joins once, avoiding a complete copy of a large document at every ancestor. Configuration editing is outside the native sample/safety loop. Tests cover full-width/huge numeric values, opaque subtree preservation, exact integer boundaries, all byte-range string escapes, Unicode/duplicate-key rejection, prototype names, pointer edits, unchanged source ownership, graph/depth limits, an 8 MiB string, canonical output and composed-edit limits. Portable verification and standalone packaging pass. Durable SQLite authority, typed document operations, receipts, assets, migration and CLI/MCP tools still require implementation.

The mobile workflow now watches native source, generated bindings/schemas, fixtures, build/probe tooling, shared workspace configuration and its own workflow. TypeScript-only contract/domain/application edits need host tests; unchanged native SDK/provider jobs need not restart for each such edit. The workflow edit itself triggers one full native run.
