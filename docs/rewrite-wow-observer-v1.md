# Portable optical pending observation and commit acknowledgement

`@thumble/application/wow-live-observer` stages one bounded immutable observation from the existing strict `WowLiveAssembler`. This is an in-memory intent boundary, with no OS capture, PNG retention, authority access, UUID mapping, profile editing, phone delivery or input activation. The existing [frame, schema and freshness contracts](rewrite-wow-live-v1.md) remain authoritative; newer schemas are rejected by that decoder rather than coerced into the supported version.

## Capture context and pending work

`observe(source, generation, frame, nowMs)` accepts a positive uint32 capture source, a canonical positive uint64 decimal generation, one existing bounded THWL frame and a nonnegative safe-integer monotonic time. The capture owner issues generations in increasing order when starting or replacing a capture context, including changing its source. A higher generation resets assembly and pending work, even if the source number stays the same. Older generations and a different source under the same generation are rejected without replacing the current context. Thus a delayed result from a previous capture cannot reclaim ownership. Callers must provide a new generation for a new source; frame payload cannot choose it.

The returned pending intent is also available through `pending(nowMs)`. It contains an increasing uint64 decimal receipt, source, generation, completing tick, message digest/length/page count, completion time, decoded snapshot and exact character identity `{flavor,id}`. Nested snapshot values follow the immutable decoder contract. At most one pending snapshot is retained alongside the decoder's bounded partial message; observing repeated frames never creates a pending queue.

A forward tick carrying a different message identity invalidates the older pending intent before the replacement message completes. Invalid pages/snapshots also clear pending work. This does not rewind the decoder's delivered-message marker or discard its previously validated partial pages: later valid continuation can complete a new message, but merely replaying the previously delivered message cannot resurrect its cleared intent. A fresh capture generation or expiry resets decoder delivery state. Frozen, backward and half-range ticks cannot supersede or freshen pending work. A source/generation change, transport expiry or time regression prevents acknowledgement of the previous receipt. Clock high-water checks prevent older query times from reviving stale work. Backward observations discard partial assembly; two advancing ticks are required again. Receipt counters never wrap: exhaustion removes publishable work and rejects each subsequent completed snapshot. The optional constructor `lastReceipt` seeds only the local counter and validates the complete uint64 range; it restores neither pending state nor durable authority receipts.

`isLive(nowMs)` retains the decoder's advancing-transport meaning. It can remain true while a newer message is partial, malformed or unsupported, with no pending snapshot. It does not mean that a snapshot has committed or that capture/gameplay acceptance passed.

## Authority completion boundary

The authority adapter must read the current pending intent, plan its profile changes against its own source revision, recheck the pending identity/freshness at the commit boundary, and perform its normal sole-writer revision-checked transaction. This module grants no write capability and cannot undo a transaction. If work is superseded while an asynchronous commit is in flight, the adapter still owns reconciliation of that transaction; a late acknowledgement returns false.

Only after a successful authority commit may the adapter call `acknowledge(identity, {kind:"committed"}, nowMs)`, passing the receipt, source and generation from that exact intent. A match that is still fresh updates the last acknowledged character identity and removes pending work. Old, mismatched, superseded or stale receipts return false. `{kind:"conflict"}` and `{kind:"failed"}` return false and retain the exact intent only while it remains current and fresh, permitting replanning rather than claiming success. Outcome values are trusted adapter reports, not proof that this module has observed a database transaction. Receipts are ephemeral process-local observation tokens, distinct from durable configuration operation receipts; this seam provides no pending recovery across restarts.

The `select` field is an intent following retained Rust observer semantics: it is true when the snapshot's exact flavor/character ID pair differs from the last successfully acknowledged pair. Names, realm display text and mere observation do not change that remembered pair. After committing character A, an A refresh has `select:false`; after committing B, returning to A has `select:true`. Source/generation changes preserve that last acknowledged pair for the observer's lifetime. This is neither an active-profile edit nor permission to override selection outside the eventual reviewed authority operation.

## Synthetic evidence and open integration

Tests exercise pending identity and immutability, failed/conflicting commit retries, stale and superseded ACK rejection, partial message replacement, replay/backward ticks, capture generation changes, time high-water behavior, unsupported snapshots, input bounds and receipt exhaustion. All data is synthetic. Existing decoder suites continue to test transport/checksum/schema limits.

The retained behavioral oracle is `Host/crates/thumble-host/src/wow_live.rs` observer and acknowledgement flow. `Sources/Bridge/WoWLiveProfile.swift` separately validates and prepares retained profile changes; that mapping/merge functionality is outside this seam. Signed capture permission, real window/scaling behavior, atlas verification, profile mapping/edit preservation, durable authority integration, phone synchronization and gameplay acceptance remain unfinished launch requirements. Manual snapshot refresh must remain available when observation is stale or unavailable.
