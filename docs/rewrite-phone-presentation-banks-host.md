# Bank-aware saved presentation host

Control role 11 explicitly negotiates presentation wire version 2. Its metadata and icon requests require one of `base`, `left-trigger`, `right-trigger`, or `both-triggers`, plus an explicit light/dark scheme. Role 10 and its version 1 exact decoders retain their base-only contract. Input role 9, credentials, grants, report encoding and input safety deadlines are unchanged.

The private native event has version 2 and a required bank. The parent converts it into a strictly decoded configuration-child query with `presentationProtocol: 2`. Both success payloads echo the requested bank and theme; the internal protocol discriminator never enters the native success payload. Limits remain 2 KiB requests, 32 KiB metadata, 16 KiB icon replies, 64 controls, 8 KiB verified 32-pixel PNGs and 65 sequential commands on a separate management connection.

The sole configuration owner uses the previously served immutable input-map proof. Its bounded eight-entry cache includes authority, old saved source revision/hash, profile, native generation/revision, exact viewport strings and materialized map hash. A current projection must preserve that installed map's IDs, geometry, actions and haptics. New saved presentation revisions do not retire input or apply new input settings. A metadata read selects exactly the requested appearance state; missing states never borrow base art. The latest verified metadata/icon cache also includes bank and theme, so a different state's icon request is stale until that state is read again. No source or resource bytes are rewritten.

For this asset-icon subset, explicit role 11 resolution preserves canonical user icon replacement/removal relative to the saved light/base reference, following retained `GamepadAppearanceBank.resolve` and `GamepadAppearanceEditMerge`. Canonical asset edits/deletions take precedence over unchanged reference entries; selected-state assets remain available when not overridden. Canonical labels and label overrides remain user-owned. Action labels are not guessed from icon names. This is not skin, paint, text-layout or full appearance rendering parity. Unsupported assets, missing references and compressed ancillary PNG metadata fail closed.

`BankPhonePresentationNotification` is separate from the legacy notification decoder. Every bank, metadata, icon and error event requires the full installed pin, exact viewport, old materialized hash, bank and theme. A `kind: bank` event carries no invented presentation revision. Native clients must derive bank changes from successfully accepted semantic trigger state: strictly greater than 0.5, with the exact 0.5 boundary staying inactive. Decoding an 8-bit report is unsuitable: 0.5 can encode to 128, and 128/255 exceeds 0.5. Touch feedback and JavaScript state are not the authority for this selection.

The synthetic shared v11 fixture contains all eight states with distinct valid PNG hashes and semantic boundary vectors. Host tests exercise strict legacy/v2 separation, full-pin native notification validation, cross-bank replay, source-preserving canonical edits and real parent/configuration-child delivery. The opt-in retained-helper test runs an actual offline prepare/SQLite refresh sequence across character changes and icon reassignment, then reads every bank and theme under the original installed input proof. It does not capture a game, authenticate observed game pixels, exercise a phone renderer or prove gameplay. SDK and actual app acceptance are separate required gates before claiming the feature complete.
