# Persistent native host TLS identity

Status: implemented for isolated headless setup and tests. Phone trust, enrollment, listener activation and production input remain separate gates.

A persistent host identity binds one private TLS key to a certificate and its exact DER SHA-256 pin. This identity survives receiver/service restarts. It is distinct from the per-process authority instance, temporary pairing window and per-activation input grant. Private key material belongs to the native receiver helper and never enters JavaScript, profile documents or CLI output.

The agent-facing commands are `thumble-rewrite identity initialize --identity-dir <absolute persistent directory>` and `identity show` with the same explicit directory. They work without a service, desktop GUI or source checkout. Initialize creates once or completes a verified interrupted creation. Show requires an initialized record and does not create/recover key material. Both return only version, certificate pin, fixed server name and disabled network/input flags. A stable pin does not grant phone trust or enable networking.

Storage uses an isolated private directory with its own `rewrite-host-identity-v1` marker, separate from the disposable receiver runtime namespace. Unix restricts it to the current user with 0700 directories and 0600 files; Windows reuses the owner/SYSTEM ACL and reparse refusal. The helper holds an exclusive `identity.lock` during initialization, recovery or inspection. Cooperating concurrent owners fail rather than generating competing identities. Existing private-directory and native storage helpers are shared by the binary and library.

The bounded private record is eight magic bytes `THID1` plus three zero bytes, unsigned little-endian u32 certificate/key lengths, then DER certificate and PKCS#8 private key bytes. Each DER field is 1–16,384 bytes; extra/truncated bytes, malformed keys, mismatched key/certificate and unsupported magic fail. Certificate loading also verifies the fixed hostname, current validity and server-auth usage through the same webpki policy as the pinned TLS client.

Initialize writes `identity.pending` exclusively, flushes it, and publishes `identity.bin` through a same-directory atomic hard link that cannot overwrite an existing record. It then removes the staging name. Unix synchronizes the parent directory at publication/cleanup boundaries; Windows flushes file contents/metadata. A valid staged-only record can complete creation under the lock. If publication completed before cleanup, matching record/staging bytes preserve the same identity and permit cleanup. Conflicting, partial or invalid material is retained and reported; it is never silently replaced. Unix additionally rejects unexpected hard-link aliases. Filesystems lacking required hard-link/locking behavior fail instead of selecting a weaker persistence scheme. Power-loss durability on supported Windows filesystems remains release acceptance work; tests cover process/interruption states, not physical power cuts.

Generated certificates retain the isolated TLS policy: five-minute not-before allowance and thirty-day lifetime. Expiry, clock-policy failure or corruption requires explicit repair/rotation work; restart does not silently generate a new pin. No production rotation workflow or migration of retained credentials is enabled. Host keys are protected by user-private storage; hardware-backed/OS secret storage for phone credentials remains a later enrollment requirement. No memory-wipe guarantee is claimed for ordinary Rust allocation lifetime.

Tests cover stable reload across separate helper processes, distinct hosts, public metadata/key separation, read-only inspection, exclusive locks, namespace isolation, interruption recovery, corrupt/conflicting records, malformed lengths/magic, key mismatch, certificate dates/name/usage and Unix symlink/hard-link rejection. Standalone package tests initialize/inspect the identity with Bun removed from PATH and no checkout. New identity source needs its own hosted Windows/macOS/Linux evidence; prior green host TLS runs exclude it.
