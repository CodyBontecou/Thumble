# Initial landscape controller hit map

`standardControllerMap(generation, revision)` in the portable domain returns a validated immutable map for the initial controller surface. Its 19 nonoverlapping rectangles cover two sticks, two held analog triggers, four face buttons, D-pad directions, shoulders, stick presses, select/start/home. Digital trigger aliases share the analog trigger report semantics and do not need duplicate on-screen controls. The caller supplies exact native-admitted generation/revision strings; this function never connects input or advances an epoch.

Coordinates are normalized within one landscape safe content rectangle. A future React Native presenter must render inside the same native input surface rectangle, account for safe insets outside that rectangle and release on resizing/rotation before admitting a replacement. This initial semantic layout is not an owned profile, preview renderer, reviewed skin, physical ergonomics result or migration/default selection for retained users. The complete app, bridge wiring, accessibility, native presentation feedback and physical acceptance remain pending.

`generate-contracts.ts` generates `controller-layout-v1.json` from the production map, including a probe for every region and a six-finger chord. `--check` refuses fixture drift. Both native engines consume that same fixture: each hit produces the retained canonical report in connected and practice mode, local native feedback follows state, practice emits no host samples, background cancellation neutralizes and delayed movement cannot revive the touch. The chord holds both sticks, both triggers, south and left shoulder for 100 native samples in each mode, then rotation neutralizes output. These tests require no React callbacks or touch queue through JavaScript. Existing TLS/UDP/native receiver tests separately exercise delivery and independent safety leases.

The TypeScript tests require every report semantic, unique intended hit regions without overlap, exact epoch bounds and immutable maps. Swift and Kotlin tests verify actual native arbitration and report encoding, including stick axes, rather than comparing a map serializer to itself. They are headless engineering evidence; signing, device latency, safe-area usability, haptics and gameplay acceptance remain open.
