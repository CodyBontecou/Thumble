# Authenticated phone catalog read seam

A trusted phone can read saved profile metadata from the same host's sole configuration authority. This adds no phone write capability, automatic profile selection, source-document download, asset access, or input activation. It does not expose the local agent endpoint, capability token, executable path, or credential to React Native.

## Separate connection and role

The native phone starts a separate management task/executor and pinned TLS connection after installing its input engine. Catalog latency or failure does not block the input sampler, UDP sender, TLS input fallback, grant renewal, or touch handling. Closing the phone connection cancels the management work independently. The existing enrollment and input clients retain their protocol versions and responsibilities.

The control-v7 hello requires `role:"management"`. The server echoes that role in hello and authenticated admission, with `inputEnabled:false` and `inputSessionAvailable:false`. Legacy hello versions reject a role field, including explicit null. Version 7 never takes the input-capable version 4–6 branch. The standalone pairing host enables this role only after its trusted parent sends the private `phone-catalog-enable` command and receives `{kind:"phone-catalog-enabled"}`.

The management connection authenticates using its native stored credential and epoch. Its single page request is `{version:1,command:"configuration-list",connectionId,expectedRevision,offset}`. The connection ID must match the authenticated binding. Revision is null or a canonical uint64 decimal string; offset is an integer in 0–255, and a nonzero offset requires a revision. Requests are limited to 1 KiB. A page is limited to 16 profiles and 32 KiB including its wire envelope. A successor page must stay pinned to the original saved revision; a mismatch returns a conflict.

## Sole authority and private correlation

The native host emits a private stdout event `{version:1,event:"phone-catalog",eventId,authorityInstanceId,expectedRevision,offset}`. Event IDs are positive canonical uint64 decimal strings, increase without wrapping during the host lifetime, and are bound to the current service authority. The parent validates exact keys, authority, monotonic correlation and the existing read-only configuration command before dispatch. A phone cannot supply a private event ID, authority, endpoint or executable.

The parent uses the existing configuration child and SQLite owner. It admits at most one underlying phone read, only when no ordinary child-bound request or bulk import/export job is active. Other child-bound operations return busy while that read is outstanding; cached import/export status polling remains available. A phone abandons its response after 2 seconds, while the single underlying read retains an explicit 30-second owner health budget. Abandonment neither queues replacement reads nor kills a healthy slow owner. When the underlying read settles, admission reopens. Malformed child replies or an unavailable owner follow the existing fail-closed child termination and service shutdown path. Input heartbeat IO remains independent throughout.

The parent decodes the ordinary configuration catalog/conflict reply before projecting it. Its private reply is `{version:1,event:"phone-catalog-reply",eventId,authorityInstanceId,result}` or the same envelope with `error`. Errors are limited to `phone_catalog_busy`, `phone_catalog_timeout` and `phone_catalog_unavailable`. Unknown or late valid correlation IDs are ignored; malformed private framing, duplicate fields or wrong authority fail closed.

The native bridge treats the parent as the trusted metadata projector. It accepts only a bounded flat scalar object, rejects duplicate keys and protected `version`, `command` or `connectionId` collisions, and adds its authenticated connection envelope. It does not parse or own the saved document. Parent and SDK codecs validate the complete metadata schema independently.

## Metadata projection and revocation

A successful flat page contains `kind:"catalog"`, `revision`, `contentHash`, `activeProfileId`, `defaultProfileId`, `nextOffset`, `profileCount`, and exactly three fields per index: `profile0Id`, `profile0Name`, `profile0UpdatedAt`, and so on. Empty revision zero has null selectors/hash and zero profiles. Names and timestamps retain the existing saved catalog bounds. Conflict contains only `kind:"conflict"` and `currentRevision`. Native SDKs remove the protected connection envelope before emitting `onCatalog`; the React Native boundary validates the first-page notification again. The controller shows only a bounded saved-profile count/status; it does not claim to have loaded or activated a saved layout.

Authorization and credential epoch are checked before the parent wait and again at delivery. Management delivery uses a separate per-scope fence. It holds that fence through the final cached check and TLS send, acquiring the input gate only briefly for validation. Input never waits on management TLS IO. Online mutation coordinators detach and mark the old scope dead under the input gate while holding their existing store/policy transaction locks. They retain its scope handle, finish broker retirement and the durable mutation, then release both global locks before waiting for management delivery. They drain that captured scope before propagating either success or a post-detachment error. Internal store invalidation only retires a scope; it never waits for management IO. Every online coordinator must retain the detached handle and perform the explicit post-lock drain before its acknowledgement. Thus a previously admitted send either finishes or is interrupted before the invalidation acknowledgement; later sends cannot use the dead scope. Peer closure interrupts blocked writes. This ordering preserves revocation without placing a network write under the input safety fence.

## Synthetic evidence and remaining work

Tests cover strict role negotiation, actual persisted credential admission over pinned TLS, metadata paging/conflicts, exact parent correlation, bounds/duplicates, late responses, revocation while waiting, independent input access during management delivery, and re-enrollment while a deliberately blocked delivery fence models a backpressured write. The latter checks global-lock release and acknowledgement ordering without claiming a real TCP-buffer backpressure reproduction. A TypeScript integration witness starts the real service, seeds its saved authority, enrolls an independent test-only TLS peer, compares its phone page with the local catalog, verifies a stale revision conflict, excludes private paths/tokens, and confirms input stays inactive. Slow-owner tests verify phone abandonment while the child remains healthy and admission remains bounded.

This is read-only metadata discovery. Editable profile synchronization, assets/rendering, phone journals, automatic discovery, real-device acceptance and gameplay remain separate requirements. Headless synthetic evidence does not certify physical input or a launch-ready product.
