# Saved profile to native phone control map

`@thumble/domain/saved-controller-map` projects a fully admitted, selected owned-v5 profile into the existing version-1 native phone `ControlMap`. This portable conversion is pure: it does not write saved settings, materialize assets, admit a phone input session, send a map, render a skin or enable output. The connected `NativeController` still uses its standard template; revision-pinned delivery and native installation are separate next seams.

The caller supplies the immutable owned document with its observed authority revision, an expected selected profile/revision/exact-source SHA-256 pin, actual native admission generation/revision, and the native input surface's safe content width/height **in logical points**. An established host SHA-256 implementation hashes the exact document UTF-8 source; imported data must never supply the digest implementation. This source hash identifies the admitted owned configuration JSON, not an external authority envelope or historical export. A source, authority revision or selected profile mismatch rejects the conversion. Saved authority revision and input admission revision remain distinct; conversion never invents or advances either epoch.

The first supported subset is explicit landscape safe content between 240 and 4096 points high and at most 4096 points wide, controller output mode, and one to 64 visible, nonoverlapping, axis-aligned rectangular buttons. Each button must have an explicit center, finite supported scales, zero rotation and zero z-index. Its effective size follows retained `GamepadCustomization.baseSize`, `controlScale` multipliers and clamped-center rules, including distinct starter 9/10 dimensions. Width/height scales are multipliers of logical base sizes, not normalized viewport dimensions. Native normalized bounds are validated again by `decodeControlMap`.

Selected profile binding records resolve using the same independent maps and retained fallback as saved selection. A present selected output map wins verbatim, including empty/sparse maps; a missing map uses each actual control's configured output (including explicit empty) before its default. Direct root mirrors and another profile are never substituted. Every visible mapped button requires exactly one known gamepad button and no keyboard binding. Chords, unknown actions, part outputs and directional mappings fail closed. There is no shared action table that can silently assign a different output to an unbound control.

Explicit complete haptic feedback uses the current native contract. Explicit legacy `none` becomes normalized no-feedback; other legacy style-only records require a future retained-normalization extension and are rejected. Missing feedback preserves the current native default. Unsupported stick/trigger/trackpad settings, nonrectangular shapes, transformed/overlapping hit regions, omitted builtin grid positions and custom-control legacy layout mirrors are rejected. Known text and decoration elements have no input region; hidden input elements produce no region. If no supported visible input remains, conversion fails.

Original source, all appearance states, resources, unknown metadata and exact numeric lexemes remain untouched. Projection does not certify appearance/image validity beyond owned admission, renderer parity or gameplay acceptance. Fixed errors identify source conflict, unsupported output mode/control kind/binding/geometry/transform/haptic/layout mirror/viewport, unbound controls, overlap, control limit, no controls or invalid map/admission. Errors include no source, asset, path or credential data.

Tests project the retained resource/appearance-bank document after explicitly saving supported rectangular controller settings, verify its actual selected binding and retained logical dimensions, and prove exact source/resource retention. Additional tests cover stale pins, independent admission epochs, sparse/empty/missing map precedence, configured/default fallback, unsupported controls, haptics, viewport/edge clamping, scale variants, 64/65 bounds, overlap and conflicting legacy mirrors. Sticks/triggers and the retained builtin default grid can extend the geometry/action helpers without weakening admission of this subset.
