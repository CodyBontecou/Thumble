# Durable iOS runtime runner stages

The synthetic iOS runtime checker now writes a separate `mobile-ios-tls-runtime-stages.json` beside its existing result report. The existing artifact glob `mobile-*.json` includes it even when the workflow's unchanged eight-minute deadline interrupts the runner before a result exists.

The journal contains only fixed stage names, fixed `started`/`completed` markers and monotonic elapsed milliseconds. It records before and after each explicit SDK lookup, compile, signing/verification, simulator runtime listing, create, boot, bootstatus, install, container lookup, launch, runtime wait, result write and simulator shutdown/delete. A started stage without completion identifies the last attempted stage; it does not prove the external call began, since diagnostic persistence itself could stall; completion means that call returned under its existing error policy, not that controller acceptance passed. No command, path, simulator identifier, endpoint, report payload or exception text enters the journal.

Each update uses a private temporary file, file fsync, atomic replacement and parent-directory fsync. The previous complete journal remains readable if a write is interrupted. There are at most 64 records and 8192 encoded bytes, with elapsed time bounded to one hour and monotonic rollback/nonfinite time rejected. Unknown stages are rejected before the external call. This journal adds diagnostic writes; it does not change existing external commands, their arguments, waiting deadlines, validation or success criteria, and it does not turn missing runtime results into passing input evidence.

This supplement starts from public commit `567bfe42452d9c2609cb68ed25f4227a3eab3dff`. Original checker blob `4c70f8ac5904538016463a5db74c24a96df679cd`, SHA-256 `29ca38de91842cb02f5e50f6394dd101b7ffa98bd0683b95594a8d096a0fc789`, is preserved in private provenance. An AST comparison verifies that external subprocess/helper/sleep calls and `validate_result` are unchanged. No unpublished app/analog harness source is copied.

The motivating hosted run `39885359320`, iOS job `120192161054`, timed out in the production runtime step after eight minutes. Its uploaded artifact contained native suite and SDK reports but no runtime result. This proves an observability gap; it does not identify a controller failure or establish which setup/runtime call blocked. The new journal is intended to distinguish that on the next run. Unit tests simulate a blocked call and verify its preceding durable record, last completed stage, failed-call behavior, hostile stages/times, fixed capacity and atomic temporary-file cleanup. No simulator, phone, game or OS input operation runs in these unit tests.

Cleanup journal writes are best-effort. A start/end metadata write, clock or capacity failure cannot prevent the original owned simulator shutdown/delete commands from being attempted in their existing order. External command exceptions still propagate under the original policy, and a failed external call never receives a completed marker. Non-cleanup stage recording remains strict. Regression tests inject failures at start, completion and every diagnostic write, mock both external cleanup calls, and preserve the original command-error behavior without creating or controlling a simulator.
