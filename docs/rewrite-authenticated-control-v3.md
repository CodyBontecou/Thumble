# Native authenticated control version 3

The native pairing owner accepts control versions 2 and 3 on its existing pinned TLS endpoint. Version 2 retains the enrollment/storage-ack/completion exchange. Version 3 authenticates an already enrolled phone. Envelope, input, document and capabilities versions remain 1. The TLS server name, ALPN, exact host pin and normal certificate validation remain unchanged. Existing CLI transport metadata advertises enrollment version 2; an authentication client explicitly proposes version 3 and must require the matching hello before sending a credential. Unsupported versions fail closed before credential transmission. This is local source; it is outside the frozen phone/vault CI candidate and earlier source approvals.

The phone sends the strict flat hello with `controlVersion:3`. The host echoes that version and its authority instance. The phone must match the expected authority and pinned host before the next frame:

```json
{"version":1,"command":"authenticate","authorityInstanceId":"authority-a","phoneId":"phone-a","credentialEpoch":"1","credential":"<64 lowercase hex characters>"}
```

The credential is bearer secret material carried only within native TLS, never over service stdio, React, configuration documents or logs. The authority, host pin, phone identity, active verifier, epoch, expiry and native clock all must pass. Unknown fields, duplicate defined fields, wrong types, noncanonical token text and wrong phases close the channel. There is no authentication fallback to a pairing window.

Successful admission replies with `version:1`, `command:"authenticated"`, `authorityInstanceId`, `phoneId`, decimal `credentialEpoch`, a random 32-character lowercase-hex `connectionId`, `expiresAt`, `inputSessionAvailable:false` and `inputEnabled:false`. No token/verifier is returned. The expiry is bounded by both credential expiry and 60 seconds from admission. The native authorization retains channel identity and metadata; it does not retain the bearer. The public identifier cannot authorize another TLS channel, a client-role channel or a closed channel.

A client may send `{"version":1,"command":"control-status","connectionId":"..."}` or `{"version":1,"command":"disconnect","connectionId":"..."}`. Replies retain the same metadata with the corresponding command (`disconnected` for disconnect). Every operation revalidates host/channel identity, epoch, active trust, native clock and expiry against the durable ledger under the shared native mutation gate. No TLS reads or writes hold the gate/database lock. A connection handles at most 128 operations; existing two-second frame deadlines apply. Disconnect, malformed messages, budget exhaustion, expiry, clock rollback and trust failure close the channel. CLI revocation additionally shuts down registered sockets immediately, including when durable storage fails; direct native ledger revocation is detected on the next operation.

[Control version 4](rewrite-native-input-control-v4.md) now adds exact-generation native grants, private receiver IPC and reliable sealed packet relay. Version 3 remains metadata-only. Physical output, native phone grant binding and UDP remain pending. Native Swift/Kotlin credential-authentication clients now implement negotiation, vault loading, metadata admission, status and disconnect; see [their lifecycle](rewrite-phone-control-v3.md). React Native wiring remains pending; existing version-2 phone clients continue to enroll unchanged.

Verification includes real native TLS enrollment/authentication/status/disconnect, distinct connection IDs, wrong-channel references, revocation, old and mismatched epochs after reenrollment, exact native socket binding, closed/client-role channels, expiry/rollback, duplicate fields and malformed token text. The standalone CLI uses an independent Node/OpenSSL test peer to reenroll, reconnect with version 3, authenticate and disconnect with no checkout or Bun on PATH. That peer is test-only and never logs its synthetic credential. Local tests do not prove Windows execution, OS credential providers, real phone networking or gameplay.
