# Native phone authenticated control

The Swift and Kotlin libraries now provide `TrustedHostEndpoint`, `PhoneControlClient` and metadata-only `PhoneControlMetadata`. An endpoint contains host, port, certificate pin and expected authority instance, without a pairing secret. Its expected authority must be refreshed explicitly when the host authority changes; this client does not silently adopt another authority or retry enrollment. It uses [control version 3](rewrite-authenticated-control-v3.md) on a new native pinned TLS connection.

Authentication first connects, verifies the exact hello/version/authority and disabled input state, then loads the credential for that host pin. Unsupported hosts fail before vault access or credential transmission. Missing, expired, unavailable or foreign-host records close the channel. The credential builds its authentication frame in native code; no new public bearer getter or serialization conformance is added. Swift's production initializer uses `PhoneCredentialWorker`, keeping Keychain I/O on its native actor; Android's production initializer uses the native vault and refuses the UI thread. A storage operation already in flight can finish after cancellation, but its result cannot start authentication after the terminal checkpoint. Existing credentials are not deleted or rewritten by this client.

Admission validates exact fields, command, authority, phone ID, canonical epoch, lowercase random connection ID, credential-bound expiry and both disabled input flags. Success returns metadata only. Status and disconnect must return identical admission metadata; a changed connection, epoch, phone or expiry is rejected. Unknown/duplicate fields and invalid types use the existing strict native flat-JSON parser. A local lease expires at the earlier of the host expiry and 60 seconds after admission. This bounds local lifetime even when clocks differ and the host's timestamp is farther ahead. Native wall-clock rollback and credential/connection expiry terminate subsequent operations before sending another request.

The Swift client is main-actor isolated around asynchronous Network.framework I/O and a storage actor. Android is a blocking native worker API with atomic one-operation admission; it is not an input-engine output callback. A second concurrent operation is rejected without queueing or disrupting the first. Close is terminal and does not wait on blocked TLS/storage work; late read/connect completions are fenced. Android closes an already registered transport on one terminal closer; a transport returned after close is retired by its connecting worker. Disconnect closes locally after the matching host acknowledgment. Reauthentication requires a new instance and never restores input touches. Calling status before admission or authenticate twice is rejected without replacing the current owner.

Control status is explicit; the client does not launch an automatic keepalive/reconnect loop. Existing host frame deadlines still apply. The input engine does not receive a grant or physical output from this exchange; native session admission, receiver handoff, packet routing and app/UI integration remain pending.

Shared synthetic fixtures and lifecycle tests cover successful exchange, hello rejection before vault access, missing/foreign/expired credentials, malformed/changed admission metadata, close/cancellation during a delayed vault read, late connect, clock rollback, expiry, bounded local lease, concurrent calls and late replies. Actual Network.framework and JDK TLS tests enroll into the real native host ledger, retain the opaque credential in a test storage owner, reconnect/authenticate, check status and disconnect. The bounded test-only host witness is never shipped with the CLI. These tests do not prove actual OS-provider vault execution, physical networking, Windows execution, haptics or gameplay. Both iOS SDK builds and Android AAR/lint compile the production clients. CI workflow witness paths are prepared, but this newer source has not been published or run on hosted runners.
