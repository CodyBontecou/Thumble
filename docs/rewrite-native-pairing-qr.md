# Native pairing QR entry

The iPhone connection prompt offers **Scan Mac QR code** alongside manual invitation entry. Scanning is explicit: opening Home, Practice, the connection prompt, or reconnecting does not request camera permission. The app explains its camera use through `NSCameraUsageDescription` in the versioned Expo configuration.

The scanner extracts QR metadata with AVFoundation. It passes at most one bounded result to the UI actor at a time, inspects at most eight metadata candidates per callback, and rejects text beyond 4096 UTF-8 bytes. Images and invitation text stay native; no camera frames, secret-bearing strings, or raw decoder errors enter React, events, logs, or status documents. Only the existing strict `EnrollmentInvitation.decode` accepts the exact TLS invitation fields. Old retained `pocketpad-pair`/WebSocket codes are unsupported. A recognized invitation still undergoes the existing pinned TLS, pairing-window expiry, proof, durable vault and host confirmation protocol; recognizing a QR code grants neither trust nor input.

The output intent is fixed by the original connection action. Scanning cannot change recording into physical mode or bypass control-v9 negotiation. Mac input requires the explicit **Connect to Mac** route; **Test a connection** remains recording. Manual entry and scanning share the same enrollment path.

Camera configuration, metadata callbacks, start and stop run on one serial native queue. One pending delivery bounds UI work. The UI's terminal scan gate rejects duplicate results, post-cancel permission callbacks and late metadata. Closing the view or backgrounding the connection retires the scan. The pre-authentication camera permission sheet may temporarily make the app inactive; it cannot start capture until the app is active. Existing input connections still retire on `willResignActive`; only the camera-only, pre-authentication phase waits for actual background before terminal connection cleanup. Camera denial/unavailability keeps native manual entry available.

The implementation extracts the QR-only AVFoundation mechanics from `Sources/iOS/QRCodeScannerView.swift`, without its SwiftUI host, old pairing admission, desktop routing, or style dependencies. The retained files remain unchanged. Deterministic SDK tests cover permission gating, cancellation, late callbacks, one accepted result, malformed/oversize/duplicate-field input, old-code rejection and redacted invitation descriptions. They do not open a camera or prompt for permission. Actual signed-phone permission, optical scanning, successful pairing, and controller delivery need separate device evidence. Android scanning and headless Mac QR image generation are separate implementations.
