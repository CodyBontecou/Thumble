# Native receiver activation and packet-source handoff

The installed recording receiver now runs `PacketRuntime` as its safety owner, including ordinary private-stdio configuration commands. Its inner `Runtime` still owns the acknowledged profile, revision, activation generation, configuration-owner session, held output, owner lease and input TTL. The native packet admission no longer needs to create a second runtime activation to use that configuration.

The trusted native `attach` operation accepts a packet grant, exact acknowledged revision and bounded lifetime. It requires the grant generation and revision to match the already active configuration. It emits a neutral source barrier and resets the sample sequence/input deadline, while preserving profile, revision, generation, owner identity and the existing owner deadline. The packet's session identity is separate from that owner identity. Attachment and input packets never renew the owner; only the actual private configuration owner can renew it. A grant arriving immediately before owner expiry cannot prolong input. Owner expiry, input expiry, grant expiry, explicit release, configuration replacement, clock failure and process/pipe failure retire packet admission through the same independent native safety path.

While a packet source is installed, ordinary recorded-sample commands fail with `packet_session_owns_input`; they cannot interleave a JavaScript sample stream with authenticated native packets. Packet decode/replay checks remain native. A new packet source starts at its own sequence zero following neutralization. Generation/revision mismatch leaves the existing source and held state intact. A failed neutral output barrier retires active input before returning the output error. Retired session IDs cannot be restored within the same activation, including after replacement or release. History is bounded to 64 sources per activation; reaching capacity requires a fresh acknowledged activation. Fresh key/nonce material remains the trusted grant producer's responsibility; this handoff does not make it safe to recreate a sender with a reused key. Native test harness `activate` remains a convenience for combined activation/grant fixtures; its legacy packet-identity renewal cannot renew a separately configured owner.

The receiver Bun pipe remains configuration/recording-only. A bounded [native IPC endpoint](rewrite-native-input-ipc-v1.md) and [control-v4 broker](rewrite-native-input-control-v4.md) now carry authenticated grants and reliable sealed input without a TypeScript sample queue. Version 3 remains metadata-only. Native phone grant/input binding now has actual Swift/Kotlin-to-receiver recording witnesses; UDP remains open. Required trust/epoch/connection checks must be revalidated before installing a grant, and revocation/disconnect must retire it. Actual OS output remains disabled and the desktop cutover is not complete.

New regression cases exercise attachment to exact acknowledged configuration, neutral sequence reset, independent owner identity/expiry, rejected recorded samples, duplicate/retired IDs, source replacement, bounded history and output-barrier failure. Existing native safety and source/standalone CLI tests still run with the actual packet-aware receiver process. This local source is newer than the approved 25-file phone/vault CI snapshot; hosted results for that snapshot do not verify this handoff.
