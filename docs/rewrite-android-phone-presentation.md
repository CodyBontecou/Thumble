# Android read-only phone presentation

`PhonePresentationClient` opens a separate pinned-TLS role 10 management connection. Construct a `PhonePresentationRequest(saved, map, colorScheme)` only from the installed saved controller. Its old configuration pin, materialized hash and exact control ID set remain fixed while labels and referenced icons can advance independently. Base light/dark appearance is supported; modifier banks and full themes are not inferred.

On a worker, call `read(request)`, then `icon(control)` for referenced uncached icons, and close the client in `finally`. Each foreground poll creates a fresh client; do not leave a connection parked between polls. A batch is limited to one metadata response and 64 icon reads. The app owns a single pending poll and its installed-map/session cancellation fence. This API has no input grant, sample, activation or persistence operations. A transport, stale-presentation or icon failure closes only this management connection.

Metadata is bounded to 32 KiB and icons to 16 KiB envelopes. Each image is canonical base64, SHA256 matched, at most 8192 bytes and exactly 32x32, noninterlaced 8-bit RGB or RGBA PNG. The verifier checks chunks/CRC, a maximum 64 chunks, contiguous IDAT, one exact bounded zlib stream and valid scan filters without a platform image renderer. Animation, unknown critical chunks and independently compressed iCCP/zTXt/iTXt metadata are rejected. An offline retained-helper icon using IHDR/sRGB/eXIf/IDAT/IEND passes the host verifier; other image formats remain a compatibility gate rather than being silently transformed.

Only verified `PhonePresentationIcon` objects can produce icon notifications. Cache reuse under a new presentation requires that metadata again references the exact icon SHA and byte count. Metadata notifications contain labels and hashes, and each icon notification contains one bounded PNG. Neither exposes source documents, paths, the atlas or credentials. Native admission and every request remain subject to host credential/revocation and active saved-binding checks.

The portable JVM tests consume `Fixtures/saved-controller-presentation-control-v10.json`, test fixed error/authority/pin/ID checks, cancellation, overlap rejection, expiry, batch limits and hostile PNG streams. A separate actual-service and app acceptance pass is required to claim the complete native-to-screen flow. No renderer, capture permission or physical output device is invoked by these SDK tests.
