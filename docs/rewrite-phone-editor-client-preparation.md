# Native editor client and coordinator preparation

This slice adds internal Swift and Kotlin codecs, frame adapters, and native journal coordinators. It does not register role 12, construct a production network client, expose a JavaScript bridge or editor screen, or enable phone configuration writes. Fake-IO tests establish protocol and local lifecycle behavior; they do not establish authenticated network acceptance. Existing roles and input authority are unchanged.

The future transport factory must create the existing certificate-pinned TLS transport and native credential source. The internal adapter negotiates exactly control version 12 and management role, checks the exact endpoint authority before loading a credential, authenticates the current phone/credential epoch, and requires the management admission's input fields to remain false. Admission uses the existing checked local 60-second cap and rejects clock rollback; the host still enforces its actual credential/session expiry. This does not remove existing credential preflight or phone-ahead clock availability limits. A connection carries one editor RPC and closes afterwards. Unknown, extra, downgraded or input-enabled fields reject. Requests and replies use the shared `phone-editor-control-v1.json` vectors with exact 2 KiB/16 KiB bounds, four-level/128-node parsing, recursive duplicate-key rejection and strict Unicode. Connection closure is not proof that an admitted owner write was cancelled.

A full profile read assembles at most sixteen eight-control pages. Every page must have the same authority, host certificate, profile, source revision/hash, profile name, total control count, authenticated phone and credential epoch. Offsets must advance exactly; control IDs must be unique across all pages. Only the complete pinned snapshot can mint an internal verified read and update the cache. A partial read, changed credential or late callback leaves the prior cache unchanged. The shared first/final page vectors are independently valid DTO cases; complete-read tests construct a coherent 18-control snapshot rather than assuming those independent vectors form one profile.

Enqueue persists the immutable intent before reporting success. Submit persists an uncertain status before invoking the transport; failed persistence produces no RPC. Admitted, pending, errors, EOF and cancellation retain the intent. Submit never automatically resends an already uncertain entry; reconciliation sends its exact original intent to the status endpoint. Only a successful authenticated exact receipt can mint the internal acknowledgment used to retire that entry. Conflicts and explicit rejection remain visible. Receipts never advance profile cache state.

Origin scope remains immutable. Both submit and status require the current endpoint authority to equal the intent's original authority. A newly resolved authority can populate a separate revision-pinned cache, but old edits return `origin-reconciliation-required`. Verified cross-restart origin reconciliation is intentionally unresolved and remains required before the complete phone editor can ship. There is no raw acknowledgment or authority-rebind bridge method.

Swift transfers a non-Sendable journal into an actor; full reply decoding runs away from the main actor, while the existing asynchronous native TLS frame interface retains its established actor boundary. A future production composition must also open the private journal away from the UI before transferring ownership. Kotlin lazily opens its journal and performs disk/network operations on a dedicated single worker with a bounded queue. Neither shares an input-delivery executor. One RPC slot remains reserved through cancellation until the old exchange actually settles, and callbacks are checked against current operation/session tokens before applying a receipt or cache. Closing/cancelling IO cannot clear the journal. Production factories and the host write-admission/drain fence remain separate integration gates.
