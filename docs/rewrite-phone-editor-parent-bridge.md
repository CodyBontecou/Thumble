# Captured configuration-owner editor bridge

This preparation is private and unregistered. It does not enable phone role12,
register a NativePairingHost handler, install an editor UI, grant a CLI/MCP write
capability, or bypass the independent native policy/commit fence.

`PhoneEditorBridge.capture` binds one actual `ConfigurationOwner` object and the
UUID minted by its child after acquiring SQLite ownership. The private enable
body contains only `command: phone-editor-enable` and `ownerLifetimeId`. The
native process must use its trusted startup runtime directory, never a path
provided in this body. A bridge never looks up a replacement owner.

Native events are exact own-data-property objects with version1, event
`phone-editor-write` or `phone-editor-read`, and an immutable envelope. Event IDs
are positive canonical uint64 strings, strictly increasing across both event
kinds for the lifetime of this bridge. Owner lifetime, authority, authenticated
phone, credential epoch and original typed request are echoed in each reply.
These private context fields must be generated by authenticated native code;
they are not additional fields accepted from a phone frame.

Writes use the existing `editor-label-commit` envelope. The bridge retains its
single write slot until the actual owner call returns, including confirmation of
child exit after uncertain transport. A read completion cannot release it.
Closing the bridge prevents future admissions and closes captured-owner editor
dispatch; it does not resolve an outstanding call. There is no write timeout race.

An actual correlated `owner-response` contains a strictly validated committed
receipt or conflict. `owner-error` proves an actual parsed owner call ended but
does not assert that a commit did not happen. `not-dispatched`, `writer-exited`
and `transport-uncertain` do not release a native dispatched ticket: native must
retire that exact writer and retain its scope/intent until an independent drain
proof is held. A malformed owner response closes this bridge and returns only
uncertain disposition. Error text is projected to a fixed allowlist.

Reads use `editor-read` with the same immutable context and a strict query of
`editor-profile` or `editor-label-status`. The actual child calls
`ConfigurationEditorReads`; no generic configuration request is tunneled.
Profile replies must match both pins, profile ID and offset. Status replies must
match the complete original label intent and its exact receipt operation,
expected revision plus one, ordered affected entities and content hash. Pending
is an unresolved receipt query and never executes the intent. Neither reply
includes raw source, paths, assets or a runtime activation.

The focused tests include an actual configuration child/SQLite lease: pinned
profile read, absent receipt, label commit, repeat original-intent receipt reads
and unchanged resulting revision. Synthetic tests hold a write open across a
read and bridge close, reject replay/context/accessor/extra-key attacks, and
retain unknown disposition on malformed replies. Full TypeScript validation and
standalone packaging are checked independently. Actual native dispatch and
policy acknowledgements still require their cross-layer integration gate.
