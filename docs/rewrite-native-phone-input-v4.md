# Native phone input over control v4

Swift and Kotlin explicitly opt into control version 4 with `inputSessions:true`. Their default remains version 3 and metadata-only control. Both require the exact negotiated authority/version over pinned TLS before loading the native credential. An authenticated response must match that connection, phone, epoch and expiry and advertise the negotiated availability with physical input disabled.

Swift `PhoneControlClient.bindInput(map, feedback:)` asynchronously reads native configuration, validates an exact active generation/revision, requests its grant and creates a main-actor input engine. Android `prepareInput(map)` runs on the native control/storage worker, then returns a single-use `PhoneInputAdmission`; `bind(feedback)` creates the engine on the native UI thread. The production Android API enforces those thread boundaries. Grant decoding, key ownership, packet sealing, touch capture and transport stay native. No raw grant is returned by either public API, and neither admission is a profile, Codable/JSON export or React event payload.

The strict grant decoder requires every documented field and rejects extra fields, noncanonical hexadecimal or counters, a different connection/configuration, a zero session, unsupported packet/transport semantics, physical input enablement, and lifetimes outside 100–60,000ms. A sender is installed only after the entire receipt validates. Each input client attempts one binding; a new source requires a new client and a fresh acknowledged configuration. Repeating a binding/handoff cannot recreate the same key/nonce counter. The existing packet format permits 2^20 nonces, while this reliable broker caps a connection at 65,536 input frames; phone senders enforce that smaller cap.

Grant lifetime is conservatively measured from before the grant request, so response latency consumes the available time. Wall-clock rollback/expiry and a continuous/elapsed deadline close input; Android also rejects elapsed-clock rollback. Admission is capped by the existing local 60-second control deadline and credential expiry. A late Android UI handoff cannot restore an expired source. No timer or sample renews the receiver's configuration-owner lease.

Binding first emits a neutral sequence-zero snapshot. The input engine owns touch IDs, local feedback and cancellation independently of React. All native lifecycle cancellations terminally close the associated transport, discard pending sealed frames and destroy the sender. Background/rotation/practice/profile change cannot reattach the old grant. Swift clears local captures during terminal close; Android UI sampling observes a failed sink and clears captures on its next native frame after a worker/network failure. UI-driven Android cancellation clears immediately. Receiver release/expiry remains independent of either UI scheduler.

Input emission never waits on socket I/O. Swift uses its bounded Network.framework adapter. Android transfers the already authenticated socket to one native reader and writer before publishing its UI handoff, retaining one replaceable input snapshot and at most eight controls in each direction. A one-second native status heartbeat validates the unchanged authenticated receipt and observes terminal failure; it also keeps Android's bounded control reader live when the host emits no unsolicited input acknowledgments. Heartbeats fit within the broker's control budget over the admission lifetime. A status reply is not a flush barrier for a coalesced sample: queued controls have priority. No delivery guarantee is inferred from that ordering. Close discards pending work and never carries it into a replacement connection.

`phone_input_probe` is a synthetic test executable, excluded from installation. It starts the actual recording receiver as a separate process, maintains an independent configuration-owner lease, and exposes bounded activation/observation commands over its test-only stdin. Native Network.framework and JVM TLS clients enroll, authenticate, bind, hold a known button through multiple heartbeats, and reconnect on an advanced generation/revision. The witness checks the exact receiver report, admitted neutral sequence zero, and `native_input_released` before its one-second observation deadline; its 1,500ms input TTL cannot substitute for that release check. Native worker/queue tests separately cover backpressure, malformed receipts, expired/late grants and lifecycle cancellation. The workflow builds both binaries and examples and explicitly enables the witness.

These are headless native transport/recording checks. JVM TLS is not Android device-provider validation, and macOS Network.framework is not physical-phone networking or rendering acceptance. The earlier c8d5d2b provider results remain evidence for that exact enrollment/vault snapshot. UDP, controller UI/app wiring, physical gamepad/keyboard/pointer output and signing, gameplay, optical live sync, retained stack-safety/cutover and all launch gates remain open. Physical input stays disabled.
