# Debug native input error evidence

`THUMBLE_REWRITE_INPUT_ERROR_PROBE=1` enables a separate debug-only error-path probe. It does not enable healthy IO spans, sampling aggregates, capture, input activation, retries, scheduling changes, or a power assertion. Release builds exclude the probe. Without the flag, it emits nothing.

Each native process emits at most the first 16 error events. Roles come from native server-thread context, rather than caller-supplied names. Events contain only fixed role/context/operation categories, a whitelisted static code, a known IO category and optional signed OS error number, or a fixed stream/server exit reason and bounded owned-grant count. No report bytes, peer identifiers, source paths, credentials, error descriptions, or window data enter these records.

The native client records IO failure and operation failure before its existing socket shutdown. A server worker records its first loop-exit category before queuing existing owned-grant cleanup. These are observed error-path events; interleaved processes and threads do not provide a globally synchronized causal clock. A later cleanup or closed-client error cannot replace an earlier retained event.

The synthetic app harness accepts `--input-error-report PATH`. This explicitly enables the native flag for its owned fixture host and writes a separate report after cleanup. The strict decoder rejects duplicate or extra fields, unknown categories, nested values, noncanonical numbers, and oversized input. It retains at most the first 32 valid events across both processes, within an 8 KiB artifact. Reports use atomic replacement and mode 0600. A report-write failure produces a fixed warning and does not replace the primary test failure or skip cleanup. Raw stderr stays private.

The native iOS CI runtime witness opts in and uploads the bounded `mobile-ios-input-error-events.json` through its existing artifact rule. Existing terminal outcomes, hold diagnostics, test deadlines, and success requirements remain unchanged. The final terminal error can be a consequence of an earlier error; this artifact preserves additional chronology rather than declaring a first cause or a stability fix.

The fixture's real service also opts into a bounded stderr chain: each `NativePipe` admits only canonical native records, and the fixture filters service stderr again before Python sees it. Each filter caps partial lines, total scanned input, retained event count, and emitted bytes. With the flag off, both layers keep their previous discard behavior. An empty artifact means no admissible events were captured; it does not certify a fault-free session.

Acceptance used a clean source tree verified against public `eca50a73e6950f10dd0cdae7fa96ab24d872cbb0`, with the separately reviewed timeout classification and this probe overlaid. Rebuilt native and Swift artifacts passed the unchanged 75-second runtime witness. A separate induced 280 ms pause of the verified, owned recording receiver exercised the nested `NativePipe` → service → fixture → Python chain: its 1,077-byte mode-0600 report retained the broker's `would-block`/OS 35 and packet timeout before receiver EOF/owned-stream exit and later closed-client failures. This positive control validates evidence plumbing and ordering; it does not explain an uninjected interruption.
