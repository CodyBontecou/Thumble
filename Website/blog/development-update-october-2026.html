release context

Since TestFlight 1.0.0 (6)

The latest uploaded iOS build is 1.0.0 (6), uploaded July 30, 2026. Its test notes cover controller editing, pairing and reconnects, orientation changes, saved profiles, and standalone Thumble Host compatibility.

This is a development update, not release notes for a new beta. The work below includes changes in the repository and experimental integrations; it is not all available in the July build or the current Mac download.

controller support

Sticks, triggers, and outputs you control

We’ve expanded the virtual gamepad implementation in both Mac receivers. Layouts can send two analog sticks, independent triggers, a D-pad, and gamepad buttons alongside keyboard and pointer controls. Each setup chooses keyboard, controller, or mixed output while retaining its own saved bindings.

Recent work strengthens held-input ownership, neutralizes old input when setups change, and adds diagnostics and explicit recovery when controller output fails. Stick dead zones, sensitivity, and inversion let you tune the feel.

Mac virtual gamepad output requires an Apple-authorized signed receiver. Live recognition by games, Steam, SDL, and Apple’s GameController framework remains a validation step. Implemented output is not a guarantee that every game will recognize a controller.

advanced layouts

A setup for the game in front of you

World of Warcraft

The new WoW Forever template combines two sticks, held triggers, face buttons, and utility controls in portrait and landscape. Keep a separate setup for each character or talent build. The game continues to own ability assignments, targeting, and action-bar pages.

For keyboard play, the experimental Thumble Link addon exports existing bindings from supported Blizzard bars. Paste the snapshot into the Mac app or CLI, review it, and create a character setup. Later imports preserve your layout and manual edits. The first adapter targets Forever interface 16001 and still needs live-client acceptance; it is not a live spell, cooldown, or class detector.

Held-trigger skin action sets can show different pictures for Base, LT, RT, and LT+RT. They change presentation while the game owns the actual actions.

League of Legends

Thumble’s custom layout tools can also make a companion pad for League: group ability keys, summoner spells, items, and ping shortcuts around your thumbs, and add a trackpad for pointer input. Match the outputs to your actual in-game bindings. This is a layout you build, rather than a new built-in preset or game integration.

Both approaches build on existing tools: separate orientation variants, groups and layers, on-device editing, thumb calibration, and Practice Mode. Those tools already existed at the July baseline; they make more involved layouts easier to refine.

AI + editing

Describe a layout, then refine it

Earlier development included a hosted MCP gateway and builder workflow. Those hosted systems are retired; the local CLI, stdio MCP adapter, and controller design tools remain. Assistants can work from templates, prepare private drafts, preview geometry, inspect layout quality, and save changes through the Mac’s configuration authority.

CSS authoring compiles visual styles into native skin packages. The Mac editor and CLI also support template-based setup editing and Quick Bind, with explicit input ownership for each control. You can keep iterating in the editor after an assistant creates the starting point.

experimental / beyond Mac

Windows and Linux receivers

A new native Rust receiver lets the iPhone send keyboard and mouse input to Windows and Linux over a local network. Verification includes native desktop input with an actual iPhone on both platforms.

This is a developer setup with a separate command-line receiver. It supports keyboard and mouse output over WebSocket; virtual gamepad output, rumble, and the Mac editor/MCP tooling are not implemented in this receiver. The main download on this site remains the Mac helper.
